# P03 closure audit

This artifact records source evidence for the bounded module-service task. The current execution
state and C01-C12 closure counts live only in [implementation status](implementation-status.md).
It is not another implementation plan. The control engine owns authored edits and explicit intents;
app-owned workers own endpoint setup, parsing, native calls, admission, recovery and cleanup.
Reuse public `golden_io` mechanisms rather than inventing another transport/retirement framework.

Audited on 2026-10-20 at `53b2de57`, with module runtime sources unchanged from `e6de11cd`.
This is an initial ownership/acceptance review, not runtime qualification. No devices, hooks,
desktop automation, process-control commands or network endpoints were operated. Existing dated
test results remain dated. A bounded item queue does not prove a retained-byte bound; a join in
source does not prove actor blocking until its caller is traced.

## Shared finish tests

Each affected package needs controlled evidence for full item/byte admission, continuous producers,
bounded actor service, startup cancellation, stopped/failed workers, retirement saturation and later
recovery. Ordered commands/events preserve accepted occurrences or return explicit rejection;
only state/latest values coalesce. Native lifetime capacity must be reserved before starting work,
and failed retirement transfer must retain ownership for a later nonblocking attempt.

Keep graph edits/backend defaults in the backend, use detached subtrees for known structural work,
and keep all existing command/script surfaces wired. Preserve current stream/HTTP/Mapping and
generator elapsed-time regression gates. Hardware, mounted UI and cross-platform qualification
remain separate; a static finding or fake-provider pass does not establish them.
