# P11 dashboard session-barrier contract

Qualify pending managed edits before the dashboard timing gate. Keep the six P11 checkpoints,
600 source widgets, three anchors and existing geometry/presentation/performance budgets unchanged.
Use the production dashboard/session and existing-path save workflow in the owned headless browser.
Controlled receipts and typed publications exercise UI consumers; no synthetic input.

The finite matrix has 114 groups:

- 96: generic/node/container sources, free move/resize and horizontal/vertical resize,
  active/confirmed work, then save, undo/redo, project transition or reparenting.
- 12: confirmed atomic ordered moves for the three source families followed by those four barriers.
  Reparenting uses a different parent from the pending move destination.
- Six: later edits during save, save failure, project snapshot recovery, host retirement,
  two confirmed widget owners and late presentation events.

Retire active unsent tails and settle admitted prefixes. Drain confirmed final samples/history before
callback entry; close managed admission through the callback. Serialize concurrent barriers. Wait
for all prefixes on failure; session retirement prevents old callback entry. Presentation-only delay
does not block completed backend work. Save retains the submitted history identity so later edits
remain unsaved. Project dispatch suspension follows managed drainage. Snapshot failure keeps the
recovery gate. Host retirement dispatches no old work/history into the replacement host.

Retain the preceding 485 browser groups/five scale tiers, all UI tests, type/Svelte checks, default
build and formatting. Backend undo/codec semantics and native disconnect/dialog/input behavior
retain separate evidence. Old-connection history cleanup is an explicit fixture step. Staged/unknown
outcomes and action timing are outside this applied-receipt matrix. The fixed three-warmup /
31-sample dashboard action matrix remains required before checkpoint closure.
