# P11 dashboard composition correctness matrix

This finite extension completes the missing container/node-widget and mixed-destination checks
before the existing composed-barrier and timing gates. It does not add P11 checkpoints or change
the six-checkpoint progress rubric.

Use the production dashboard, session pipeline and explicit presentation commands in the owned
headless browser. Keep 600 logical source widgets and three destination anchors. Registered node
content uses the public widget registry; containers retain their logical subtrees. Existing sparse,
dense, hierarchy, generic/free/ordered and retained-header cases remain required.

For container and registered-node sources, exercise move under all six parent layouts; exercise
resize in free/horizontal/vertical and refusal in grid/tabs/accordion. Check mounted identity,
actual geometry, bounded presentation, final receipts and owned history. Include confirmed work
through disposal and rejected work. The existing per-surface/page presentation budgets and
0.5 CSS-pixel geometry tolerance stay fixed.

Move each generic, registered-node and container source from a free parent into all six destination
layouts. Ordered targets insert before the middle of three real anchors (index one); free targets
receive viewport-derived placement. Check the exact destination and authored insertion identity,
plus actual mounted source content after publication. Fixture receipts/events exercise consumers;
backend layout policy retains the real-engine tests from the preceding milestone.

For active free and constrained transforms, change root/local fonts, parent size, zoom/pan/scroll
or viewport dimensions while a first receipt is held and a newer sample is pending. Coordinate-frame
changes must retire stale unsent work before further writes; admitted work keeps its authoritative
outcome and its history closes. Confirmed work remains valid across later view changes. Use no
recurring polling. These correctness cases do not establish physical-input behavior.

The fixed extension has 164 correctness groups: 24 container/node parent-layout cases, 18 mixed
destinations, 78 frame changes (three source families, four transform contexts, six changes each,
plus actual horizontal/vertical scrolling), 24 free/constrained disposal/rejection cases and 20
ordered container/node move disposal/rejection cases. Scroll probes constrain the existing parent
viewport before starting; they retain all 600 source widgets. An explicit canvas unmount tests view
disposal even when the small top-level ordered collection correctly stays mounted offscreen.

After this matrix, qualify host/project/reparent/save/undo barriers over confirmed pending work,
then the existing three-warmup / 31-sample action matrix at 1k/10k/20k/50k/100k authored nodes.
Preserve 200ms feedback/stall and 2,000ms completion normal ceilings; stress 400ms / 4,000ms.
No setup observation or correctness count closes that timing gate. Native usability retains P17.
