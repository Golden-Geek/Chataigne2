# Dashboard drop repair

Last updated: 2026-11-12. Scope: one regression acceptance gate; 1/1 accepted (100%).

| Gate | State | Required evidence |
| --- | --- | --- |
| Dropped widgets retain authored placement | Accepted | Exact rejection reproduced; all 18 widget/layout creation combinations, placement values, undo/redo, full engine library tests and strict lint pass. |

Deliverable: restore Dashboard widget drops in `golden_engine`, which owns conditional
layout parameters and prepared creation. The regression exercises node, generic and container
creation intents with placement in all six supported layouts. Scope cutoff was 15:30
Europe/Paris on 2026-11-12; final verification completed afterward without expanding the repair.

The baseline reproduced the exact `InitializePreparedItem` rejection for `layout/width`.
Internal preprocessing suppressed snapshots even for generated nested/conditional
declarations, so layout dependency predicates could not see the live parent and removed
width/height. The repair adds an independent internal snapshot requirement, generated by the
Params DSL and forwarded through composed nodes and node enums. Snapshot-free nodes retain
their existing path; other nodes share the existing cached, incrementally refreshed snapshot.

Creation also had a separate path-based parent-layout lookup that silently returned `free`
for horizontal/vertical layouts and supplied absent dimensions. It now uses the bounded
declared-field lookup shared with move/resize and propagates invalid-surface errors.
