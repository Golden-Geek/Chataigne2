# Contributor Map

This repository is the Chataigne2 app shell plus transitional checkouts of the shared Golden
runtime and UI packages. When in doubt, add code at the narrowest layer that owns the behavior.

## Chataigne2 App Code

Chataigne2 owns product-level composition:

- `src/main.rs`: the thinnest executable entry point.
- `src/app/`: app lifecycle wiring, default project setup, and launch through the
  reusable `golden_core` host.
- `src/module/`: Chataigne-specific module nodes, module manager policy, module authoring rules,
  reference filters, and concrete module families.
- `capabilities/`, `icons/`, `tauri.conf.json`: app packaging and host permissions.
- `src-ui/src/routes/` and `src-ui/src/lib/assets/`: app routes, branding, and product-specific UI
  assets.

Add a new Chataigne app node under the cohesive app-owned feature tree that owns it, usually
`src/module/` for module-related nodes. Stable node IDs and default labels belong on the node's
`#[node(...)]` declaration. User-creatable catalog metadata belongs on `#[item(...)]` in the node
file, so managers and project creation do not repeat module type strings or labels.

## golden_core

`submodules/golden_core/` owns reusable Rust behavior:

- engine runtime, node primitives, parameter semantics, and script support;
- protocol DTOs and persistence contracts;
- transport server, desktop/headless host, and native dialogs;
- macros and build/codegen support crates.

Do not path-import private files from this submodule. If app code needs a reusable capability, add
or use a public crate/facade boundary.

## golden_ui

`src-ui/src/lib/golden_ui/` is treated as the reusable UI package boundary even while it still lives
inside the app tree. It owns reusable Svelte components, stores, transport adapters, host bridges,
and generated Rust protocol bindings. Keep package-internal imports relative and do not add `$app/*`
dependencies there.

App routes should consume `golden_ui` through package exports where possible. Product-only panels,
branding, and assets belong outside `golden_ui`.

## Generated Code

Generated artifacts are implementation output, not hand-authored source:

- `OUT_DIR/app_nodes.rs`: generated by `build.rs` through `golden_codegen_support`.
- `OUT_DIR/ui_assets.rs`: generated by `build.rs` from the bundled UI build output.
- `src-ui/src/lib/golden_ui/generated/rust_protocol/`: TypeScript bindings generated from Rust DTOs.
- `gen/schemas/`: generated Tauri schemas.
- `Cargo.lock` and `src-ui/package-lock.json`: lockfiles produced by package managers.

Do not manually edit generated protocol files. Change the Rust DTO/generator source, rerun the
generator, and commit the regenerated output with the consumer changes.

## Build Switches

`build.rs` builds and embeds the UI bundle by default. These environment switches are available for
local and CI workflows:

- `GC_FORCE_NPM_CI=1`: refresh UI dependencies before building.
- `GC_SKIP_UI_BUILD=1`: compile without bundled UI assets.
- `GC_UI_ASSUME_BUILT=1`: embed the existing `src-ui/build` output instead of running Vite.

For first-time local setup, use `.\tools\dev.ps1` on Windows or `bash ./tools/dev.sh` on macOS/Linux.
Those scripts install or verify the host toolchains, initialize submodules, run `npm ci` when needed,
and then delegate to `cargo run`.

## Intentional Naming

Chataigne project files use the `noisette` file extension. That naming is intentional app
compatibility and should not be renamed unless a migration is explicitly planned.

## Validation Checklist

Run what is available locally before handing off:

```sh
cargo fmt --check
cargo clippy --all-targets -- -D warnings
cargo test
cargo check
```

```sh
cd src-ui
npm ci
npm run check
npm run build
```

Use `tools/check.ps1` for the documented local guardrail pass on Windows once the bootstrap command
has prepared Rust and Node on the shell PATH.
