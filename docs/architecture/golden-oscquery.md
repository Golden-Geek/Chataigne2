# Golden OSCQuery

The shared desktop and headless host adds **Preferences → OSCQuery**. The folder starts disabled. When enabled, its **Port** publishes the current node hierarchy over HTTP on the local machine. MapGyver defaults to 43000 and Chataigne to 42000. The port is saved with application Preferences. Edits rebind the listener, and an occupied port is retried while the preference remains enabled.

`GET /?HOST_INFO` reports the application's name and supported attributes. Browse the entire hierarchy with `GET /`, request any child by `FULL_PATH`, or request individual attributes such as `?VALUE` or `?RANGE`. Each response uses one immutable Golden projection, so the address, metadata and values describe the same revision. The transport reads that projection off the engine thread. [OSCQuery proposal](https://github.com/Vidvox/OSCQueryProposal)

A segment uses the Golden node's short name when it is unique among its siblings and consists of ASCII letters, digits, underscores or hyphens. An invalid, empty, overlong or duplicate short name uses `~` followed by the node UUID without hyphens. This keeps every node independently addressable. The root is `/`. Boolean values use integer `0` and `1`, vectors and RGBA use float components, and reference values use the target UUID. Request a smaller subtree if a response exceeds the host's 32 MiB or 256-level limit.

This checkpoint is local and read-only. The remaining OSCQuery gate covers LAN discovery and ZeroConf, OSC input, client-specific WebSocket feedback, manager and metadata intents, and copying or showing the current path in the Inspector. The local `juce_organicui` reference uses `ADD`, `REMOVE`, `RENAME` and `MOVE` commands and accepts string, array and object payloads for `LISTEN`; those are the compatibility references for the corresponding Golden intent and subscription work. [Legacy OSC remote control](https://github.com/benkuper/juce_organicui/blob/master/remotecontrol/OSCRemoteControl.cpp)
