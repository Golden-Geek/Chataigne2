# UI Protocol

The canonical UI wire protocol lives in the standalone Rust `golden_protocol` package and is
consumed by engine adapters, transport hosts, code generation, and the Svelte client.

## Current State

- Rust DTOs are defined by responsibility under
  `crates/golden_core/services/protocol/src/types/`. They depend on foundation and script-contract
  types, not on the engine, QuickJS, transport, or desktop host.
- `crates/golden_core/services/protocol/src/lib.rs` is the direct protocol-only public boundary;
  the ready-to-launch `golden_core` facade also re-exports it as `golden_core::ui_sync`.
- `crates/golden_core/engine/src/ui_sync.rs` coordinates intent application. Its sibling
  `ui_sync/conversion.rs` maps engine data into canonical DTOs, `ui_sync/creation.rs` owns
  user-item/dashboard creation and duplication, `ui_sync/removal.rs` validates multi-selection
  deletion and retains only outermost selected roots, and `ui_sync/snapshot.rs` owns scoped
  snapshots, node/event projection, and read-only control information. These are engine adapters,
  not a second protocol declaration site.
- Raw transport bindings are generated into `packages/golden-ui/generated/rust_protocol/` by the
  root workspace codegen command.
- Generated binding files carry a `Do not edit this file manually` header from `ts-rs`; treat that
  directory as generated output.
- The generated `protocol-version.ts` binding comes from the Rust
  `UI_PROTOCOL_VERSION` constant; transports must not hard-code a second version string.
- `packages/golden-ui/transport/codecs/{values,documents,projects}.ts` converts generated
  Rust-wire types into the UI-local models in `packages/golden-ui/types.ts`. HTTP delivery and
  socket bookkeeping stay in their focused transport modules.
- Session capabilities, bootstrap requests and credential responses also belong to `golden_protocol`.
  The transport host admits operations before engine dispatch; the shared client session helper
  consumes generated types and server-prepared WebSocket offers. See the
  [request/session boundary](ui-transport-security.md) for lifetime, privilege and renewal ownership.
- `types.ts` is a frontend model layer, not a second source of truth for the wire protocol.
- `crates/golden_core/engine/src/ui_read_model.rs` maintains an incremental graph projection,
  indexed retained-event replay, and a bounded cache of completed immutable whole-graph snapshots.
  Projection nodes and parent indexes use fixed-shard copy-on-write stores. Capturing a revision
  clones only a fixed set of shard roots while holding the projection lock; DTO materialization and
  JSON encoding happen after that lock is released.
- Each immutable capture owns its event revision and project generation alongside its projection
  roots. Later edits copy only affected shards, so a slow snapshot consumer cannot observe a mix of
  revisions or block publication for whole-graph materialization. The transport admits captures to
  one bounded background encoder, retains at most one completed whole-graph JSON payload, and shares
  that immutable payload across clients requesting the same version. HTTP request workers wait only
  for their admitted result; the WebSocket hub polls completions and continues control/replay work.
  Superseded read-model and encoded state is dropped on background workers rather than the control
  actor.
- Production mutations collect and publish their projection delta within the same ordered control
  actor turn. A later mutation or project replacement therefore cannot publish ahead of an older
  capture.
- Project replacement materializes its complete projection before cutover. The internal projection
  header carries the same monotonic project generation as the actor-owned engine; installation
  clears old replay retention and publishes the replacement resync event at that one boundary.
- One WebSocket replay pass delivers its non-empty data planes in one atomic delta envelope.
  The client stages the whole envelope before rendering and drains large event bursts in bounded
  animation-frame slices, preserving global event-time order and keeping input responsive. Detached
  graph work has both a 512-unit ceiling and a four-millisecond default wall-clock budget per frame;
  elapsed time is checked at each safe projector work boundary.
- Published browser graph indexes use fixed-depth persistent numeric tries. Each transaction forks
  the four index roots in constant time and copy-on-writes only touched hash paths; it never clones
  every pre-existing node, child, parent, or parameter entry. Detached large-event projection still
  publishes all four roots and its cursor atomically. Subtree removals consume the protocol's
  authoritative `removed_ids` list incrementally rather than recursively walking the live tree.
  Retaining an older published version retains shared trie structure plus only the changed paths;
  lookups never traverse a version-overlay chain.
- Mixed graph transactions use the same detached projector. Node moves and child-order patches walk
  their authoritative child lists incrementally; node metadata and parameter patches apply to that
  detached version before one atomic event/cursor publication. Transport decoding canonicalizes
  parameter patch values, controls, and constraints before the store sees them.

## Rules

Rust parameter constraints store enum domains in the immutable foundation type
`ParameterEnumOptions`. Cloning constraints, process snapshots, or retained typed history records
shares one `ParameterEnumDomain`: authored option rows, sorted membership indexes and a cached
allocation charge. Producers freeze the complete vector before publishing; construction sorts on
the producing boundary. Readers use binary search and cached weights. No mutable collection API
is exposed. Native producers may adopt a canonical `Arc<ParameterEnumDomain>` to preserve lifetime
admission for both rows and indexes through exported constraints and raw shared handles.

Serialization remains an ordinary option array in authored order, and Rust's TypeScript annotation
generates that same array contract. Derived indexes and weights are native metadata, never wire
fields. Membership rejection reports a bounded count rather than serializing every allowed ID.
Wire projection and project serialization can still materialize copies; project deserialization
rebuilds indexes. Shared Rust storage does not remove those publication costs by itself.

In-memory history and callback restoration use the opaque `NodeAuthoredData` contract, separate
from project JSON. The built-in Parameter captures all authored fields natively, preserving the
exact shared enum domain and its original admission through restore, undo and redo. Generated
node wrappers compose the inherited native capture with their complete declared fields, including
defaults. Restoration consumes a capture, moving unique native fields when possible. Node
metadata and topology remain Engine-owned; runtime resources stay with the live node. These
captures are for the same live node, not transferable project records.

Manual nodes default to their JSON project codecs. Generated nodes with a custom project encoder
also retain the JSON path, paired with the project decoder; a custom authored capture/restore pair
may override it. A decoder-only project-load reset does not replace generated complete-field
restoration. Native parameter equality includes persisted reference hints but excludes runtime
cached node IDs. Custom JSON codecs and copied non-enum fields retain their existing costs.

Kind coercion lives in the parameter foundation. `coerce_param_value_for_target_ref` borrows an
unchanged source, while `coerce_param_value_for_target_owned` moves accepted storage. The owned
result API copies unchanged borrowed storage only for its final result. Text-to-text conversions
move an owned string when allowed; file paths still cannot become enum IDs. Explicit forward and
reverse projections retain their target-component semantics, and CSS sources keep their units.
Compatibility checks use borrowed coercion instead of cloning an entire source first. Conversion
that formats text or parses numeric/vector/CSS input retains its existing work and allocations.

Constraint replacement validates the current value by reference and assigns a value only when
normalization changes it. Rejection preserves both value and constraints. Parameter preparation
and typed history restore consume accepted input. These guarantees avoid intermediate copies;
full snapshots, events, history capture and wire publication still have their own costs.

- Request, response, event, snapshot, and protocol-version types must have one source of truth.
- DTO changes must update the generator, generated output, and consumers together once generation is in place.
- Do not introduce new manual Rust/TypeScript wire mirrors.
- Keep frontend-only convenience types and normalization logic in the adapter/model layer instead of copying raw protocol declarations.

## Current Consumers

- The built-in HTTP and WebSocket host in `crates/golden_core/hosts/transport/src/ui_server/mod.rs`.
- The UI transport client in `packages/golden-ui/transport/`.
- The UI workbench/session stores through the normalized types in `packages/golden-ui/types.ts`.
