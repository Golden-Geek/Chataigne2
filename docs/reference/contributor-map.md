# Contributor Map

This repository is the complete Chataigne product and reusable Golden stack in one monorepo. Add
code at the narrowest layer that owns the behavior.

## Ownership

- `apps/chataigne/` owns product composition, app lifecycle, concrete modules, module scripting
  templates, Alchemist, state-machine policy, desktop resources, and product-specific UI.
- `apps/chataigne/systems/alchemist/` owns formulas, conditions, processors, Inputs, Filters, and
  Outputs. `apps/chataigne/systems/state_machine/` owns the state/transition runtime.
- `crates/golden_core/` owns the reusable Rust framework, grouped into engine, foundation,
  runtime, service, host, and support areas.
- `crates/golden_graph/` owns the generic graph document and transaction system.
- `packages/golden-ui/` owns the reusable workbench UI, `packages/golden-audio-ui/` owns generic
  audio device presentation, and `packages/golden-graph-ui/` owns the reusable graph canvas.
  Alchemist- and Sound Card-specific UI belongs under `apps/chataigne/ui/`.

Cross these boundaries only through public Cargo crates or JavaScript package exports. Do not use
filesystem path imports into another crate's or package's private source.

Tests follow the same ownership map: put each suite in a `tests/` directory beside its owning
feature. Reserve a crate's top-level `tests/` directory for integration coverage and fixtures; do
not create loose test files next to runtime sources.

## Generated code and locks

- `OUT_DIR/app_nodes.rs` and `OUT_DIR/ui_assets.rs` are generated by `apps/chataigne/build.rs`.
- `packages/golden-ui/generated/rust_protocol/` is generated from canonical Rust DTOs.
- `packages/golden-audio-ui/generated/` is generated from `golden_audio` Rust DTOs.
- `apps/chataigne/ui/src/lib/systems/state_machine/generated/` is generated by the app
  state-machine crate.
- `apps/chataigne/gen/schemas/` contains generated Tauri schemas.
- Root `Cargo.lock` and `package-lock.json` are the only workspace locks.

Change generator inputs, regenerate, and commit outputs with their consumers. Do not hand-edit
generated protocol declarations.

## Root workflows

Fresh setup and launch:

```powershell
.\tools\dev.ps1
```

```sh
bash ./tools/dev.sh
```

Normal entry points are `cargo run`, `watch`, and `cargo run -- --dev`, all from the repository
root. UI commands also run from the root (`npm ci`, `npm run check`, `npm test`, `npm run build`).
No submodule setup is required.

`GC_FORCE_NPM_CI=1` refreshes root UI dependencies, `GC_SKIP_UI_BUILD=1` compiles without bundled UI
assets, and `GC_UI_ASSUME_BUILT=1` embeds the existing `apps/chataigne/ui/build` output.

Run `tools/check.ps1` for the local guardrail pass. Chataigne project files intentionally use the
`noisette` extension; do not rename it without an explicit migration.
